# PageTurn redesign brief

Use this prompt as the product and visual brief for future PageTurn work.

> Redesign PageTurn as a complete browser based EPUB reading system. Start with the reader and build the rest of the product around the habits of reading: discovering a title, importing it, finding the right place to begin, settling into a chapter, keeping useful passages, and returning later.
>
> Make the reading canvas feel like a well made instrument: content first, controls quiet until requested, comfortable single page and continuous reading, adjustable type size and line spacing, warm paper, dark and OLED themes, table of contents, in book search, bookmarks, highlights, personal notes, dictionary, read aloud, focus timer, keyboard navigation, offline access, and clear progress. Make notes useful beyond one session with a searchable notebook that spans books and exports cleanly to Markdown.
>
> Give the library practical structure: a Today view that resumes the most recently read active book, an intentional reading queue, current reading, finished books, search, collections and import. History and insights should help a reader understand their own rhythm without turning the product into a business dashboard.
>
> Use a restrained, editorial visual language appropriate to a serious publishing company: native system sans serif for interface text, an installed system serif for book and literary moments, paper and graphite surfaces, one considered evergreen accent, clear typography, generous spacing, hairline dividers and consistent alignment. Avoid display fonts, gradients as decoration, neon, faux leather, page curl, heavy nested cards, AI looking illustrations, and decorative motion without a purpose.
>
> Use motion to clarify state and make navigation feel responsive: subtle view entrance, progress feedback, small hover lifts for covers, and short crossfades. Keep the reading page still, do not animate content as the reader reads, and honor reduced motion. Design mobile and desktop as first class reading contexts. Preserve accessibility, keyboard operation, contrast, robust offline behavior, and a calm professional tone.
>
> Before implementation, inspect the existing routes, data model, reader controls and app conventions. Extend existing features where possible, implement working flows rather than decorative mockups, keep server actions scoped to the signed in user, and verify each new route and interaction against the installed framework documentation.

The visual direction follows the AGY design consultation: a “digital paper sanctuary” with a content first reader, near zero chrome while reading, restrained system typography and functional motion.
